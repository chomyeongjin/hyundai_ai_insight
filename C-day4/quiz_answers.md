### Q1-1. fopen 이 실패했을 때 반환값과 올바른 처리는?

```c
FILE *fp = fopen("temps.txt", "r");
____
```

① 0 을 반환, 무시해도 된다  
**② NULL 을 반환 — 사용 전에 검사하고 perror 로 원인 출력** ✅  
③ 예외를 던진다  
④ -1 을 반환  

> **정답: ② NULL 을 반환 — 사용 전에 검사하고 perror 로 원인 출력**  
> 해설: 검사 없이 fgets(…, fp) 하면 NULL 역참조로 세그폴트. Day 2 malloc 검사와 같은 규칙입니다.  
> 확인: D4-1 · nope.txt

```c

```

① "r"  
② "w" — 새로 쓰기  
**③ "a" — 끝에 덧붙이기** ✅  
④ "r+"  

> **정답: ③ "a" — 끝에 덧붙이기**  
> 해설: "w" 는 기존 내용을 지우고 시작합니다. 오늘 가장 흔한 사고가 로그를 "w" 로 열어 이전 기록이 사라지는 것.

### Q1-3. 아래 코드에서 errno 를 먼저 변수에 복사한 이유는?

```c
if (!fp) {
    int err = errno;
    printf("...");
    perror("fopen");
}
```

① errno 가 지역 변수라서  
**② errno 는 전역이라 그 뒤에 부른 함수(printf 등)가 덮어쓸 수 있기 때문** ✅  
③ perror 가 errno 를 0 으로 만들어서  
④ 문법 규칙  

> **정답: ② errno 는 전역이라 그 뒤에 부른 함수(printf 등)가 덮어쓸 수 있기 때문**  
> 해설: 실패 직후 읽어야 정확합니다. MCU 에서는 errno 대신 반환값 규약을 씁니다(6교시).

### Q1-4. 파일을 2000번 열고 닫지 않는 루프를 돌리면 어떻게 됩니까?

```c

    FILE *fp = fopen("temps.txt", "r");
    // fclose 없음
}
```

① 문제 없음  
**② 약 1000번째에서 fopen 이 "Too many open files" 로 실패한다** ✅  
③ 메모리 부족으로 죽는다  
④ 컴파일 에러  

> **정답: ② 약 1000번째에서 fopen 이 "Too many open files" 로 실패한다**  
> 해설: 프로세스가 동시에 열 수 있는 파일 수 한계(보통 1024)입니다. fopen/fclose 는 malloc/free 와 같은 짝 규칙.
