### Q1-1. 아래 코드에서 p 에 저장되는 것은 무엇입니까?

```c
int x = 5;
int *p = &x;
```

① x 의 값 5  
**② x 의 주소** ✅  
③ x 의 복사본  
④ 0  

> **정답: ② x 의 주소**  
> 해설: & 는 주소 연산자입니다. p 는 x 가 있는 메모리 주소를 담고, *p 로 그 주소의 값에 접근합니다.  
> 확인: D2-1

① 5  
**② 42** ✅  
③ 주소값

> **정답: ② 42**  
> 해설: *p 는 "p 가 가리키는 곳"이고 그곳이 바로 x 입니다. 화살표를 따라가 값을 쓴 것입니다.

### Q1-4. Day 1 의 inc(int x){ x++; } 는 원본을 바꾸지 못했습니다. 아래처럼 고치면 원본이 바뀌는 이유는 무엇입니까?

```c

```

① x 가 전역이 되어서  
**② x 의 주소를 넘겨 함수가 그 자리에 직접 쓰기 때문** ✅  
③ ++ 가 두 번 적용돼서  
④ 포인터는 값을 복사하지 않아서  

> **정답: ② x 의 주소를 넘겨 함수가 그 자리에 직접 쓰기 때문**  
> 해설: 여전히 값 전달이지만 전달되는 값이 "주소"입니다. 함수는 그 주소를 따라가 호출자의 변수를 수정합니다.

### Q1-6. 아래 코드에서 첫 번째 printf 가 출력하는 값과 그 직후 p 가 가리키는 곳은 무엇입니까?

```c

int *p = arr;
printf("%d\n", *p++);
```

① 3 을 출력, p 는 arr[0] 그대로  
**② 3 을 출력, p 는 arr[1]** ✅  
③ 4 를 출력, p 는 arr[0]  
④ 1 을 출력, p 는 arr[1]  

> **정답: ② 3 을 출력, p 는 arr[1]**  
> 해설: 후위 ++ 가 * 보다 우선순위가 높아 *p++ 는 *(p++) 입니다. 현재 값을 쓴 뒤 포인터를 다음 칸으로 옮깁니다.

## 2교시 · 포인터 산술과 const

🎬 관련 애니메이션: D2-2 p+1 은 몇 바이트

### Q2-1. int *p 에서 p + 1 은 몇 바이트 뒤의 주소입니까? (x86-64)

```c
int arr[5];
int *p = arr;
printf("%p %p\n", p, p + 1);
```

① 1  
**② 4** ✅  
③ 8  
④ 알 수 없다  

> **정답: ② 4**  
> 해설: p + n 은 n × sizeof(*p) 바이트 이동합니다. int 는 4바이트이므로 p + 1 은 4바이트 뒤입니다.  
> 확인: D2-2 · int *

---

### Q2-2. double *q 에서 q + 2 는 몇 바이트 뒤입니까?

① 2  
② 8  
**③ 16** ✅  
④ 24  

> **정답: ③ 16**  
> 해설: 2 × sizeof(double) = 2 × 8 = 16 바이트입니다. 타입이 보폭을 결정합니다.  
> 확인: D2-2 · double *

### Q2-3. 아래 뺄셈의 결과는 무엇입니까?

① 16 (바이트 수)

> 해설: 같은 타입 포인터끼리의 뺄셈은 바이트가 아니라 요소 개수입니다. 바이트 차이를 보려면 (char *) 로 캐스팅합니다.

### Q8-1. 분석기의 입력 루프로 알맞은 것은 무엇입니까?

```c
char line[64];
while (____) {
    ...
}
```

① scanf("%s", line) == 1  
**② fgets(line, sizeof line, stdin)** ✅  
③ gets(line)  
④ read(line)  

> **정답: ② fgets(line, sizeof line, stdin)**  
> 해설: fgets 는 EOF 에서 NULL 을 돌려주므로 while 조건으로 바로 쓸 수 있고, 버퍼 크기를 넘지 않습니다. gets 는 표준에서 제거됐습니다.  
> 확인: D2-8 · 줄 읽기

if (!parse_frame(line, &r)) {

```c

```

① 속도  
**② 입력이 몇 줄인지 미리 알 수 없기 때문** ✅  
③ 구조체는 스택에 못 둬서  
④ 정렬을 위해  

> **정답: ② 입력이 몇 줄인지 미리 알 수 없기 때문**  
> 해설: 줄 수를 모르면 고정 크기 배열은 넘치거나 낭비됩니다. cap 을 두 배씩 키우면 realloc 횟수는 log₂n 번뿐입니다.

### Q8-4. sizeof *log 라고 쓴 이유는 무엇입니까?

```c
Reading *log = malloc(cap * sizeof *log);   // sizeof(Reading) 대신
```

① 짧아서  
**② log 의 타입이 바뀌어도 크기가 자동으로 따라오기 때문** ✅  
③ sizeof(Reading) 은 컴파일 안 돼서  
④ 포인터 크기를 구하려고  

> **정답: ② log 의 타입이 바뀌어도 크기가 자동으로 따라오기 때문**  
> 해설: 타입 이름을 두 번 적지 않는 관용구입니다. 나중에 Reading 을 다른 타입으로 바꿔도 이 줄은 고칠 필요가 없습니다.  
> 확인: 8교시 뼈대

### Q8-5. Reading 구조체 두 개를 맞바꾸는 방법으로 옳은 것은 무엇입니까?

```c
if (a[j].t > a[j + 1].t) { ____ }
```

① swap(&a[j], &a[j+1]) — int 용 swap 그대로  
**② Reading t = a[j]; a[j] = a[j+1]; a[j+1] = t;** ✅  
③ memcpy 만 가능  
④ 구조체는 대입이 안 된다  

> **정답: ② Reading t = a[j]; a[j] = a[j+1]; a[j+1] = t;**  
> 해설: 구조체는 = 로 통째로 복사됩니다. int 용 swap 은 타입이 달라 쓸 수 없습니다(Day 3 에서 void * 와 함수 포인터로 일반화).  
> 확인: D2-8 · 정렬

### Q8-7. n 이 0 일 때 통계를 계산하지 않고 바로 끝내는 이유는 무엇입니까?

```c
if (n == 0) { printf("데이터 없음\n"); free(log); return 0; }
```

① 속도  
**② log[0], log[n-1] 이 배열 밖이고 평균은 0 으로 나누게 되기 때문** ✅  
③ free 를 먼저 해야 해서  
④ C 규칙  

> **정답: ② log[0], log[n-1] 이 배열 밖이고 평균은 0 으로 나누게 되기 때문**  
> 해설: 빈 데이터는 특수 경우입니다. 이 한 줄이 없으면 log[-1] 접근과 0 나누기가 동시에 일어납니다.  
> 확인: 8교시 뼈대

### Q8-8. 제출 조건 "valgrind definitely lost 0 bytes" 를 만족시키려면 무엇이 필요합니까?

```c
valgrind --leak-check=full ./analyzer < log.txt
```

① printf 를 줄인다  
**② 모든 경로(정상 종료, 데이터 없음, realloc 실패)에서 free(log) 가 호출되게 한다** ✅  
③ malloc 을 안 쓴다  
④ realloc 을 안 쓴다  

> **정답: ② 모든 경로(정상 종료, 데이터 없음, realloc 실패)에서 free(log) 가 호출되게 한다**  
> 해설: 조기 return 하는 경로에서 free 를 빠뜨리는 것이 가장 흔한 누수입니다. 뼈대의 세 return 을 모두 확인하세요.
