### Q1-1. 아래 코드에서 s 의 세 필드 값은 각각 무엇입니까?

```c
typedef struct { double t; int h; int d; } Reading;
Reading s = {.d = 150, .t = 36.9};
```

① 36.9, 150, 0 — 지정한 순서대로  
**② 36.9, 0, 150 — 지정하지 않은 h 는 0** ✅  
③ 컴파일 에러 — 순서를 바꿀 수 없다  
④ 36.9, 쓰레기값, 150  

> **정답: ② 36.9, 0, 150 — 지정하지 않은 h 는 0**  
> 해설: 지정 초기화(C99)는 필드 이름으로 값을 넣고, 빠진 필드는 0 으로 채웁니다.  
> 확인: 1교시 예제 1-1

### Q1-2. 구조체를 다른 변수에 대입한 뒤 복사본을 고쳤습니다. 출력은?

```c
Reading r = {25.3, 60, 120};
Reading c = r;
c.t = 99.0;
printf("%.1f %.1f\n", r.t, c.t);
```

① 99.0 99.0 — 같은 메모리를 가리킨다  
**② 25.3 99.0 — 통째로 복사된 독립 사본** ✅  
③ 컴파일 에러 — 구조체는 대입 불가  
④ 25.3 25.3  

> **정답: ② 25.3 99.0 — 통째로 복사된 독립 사본**  
> 해설: 구조체 대입은 memcpy 와 같은 통째 복사입니다. 배열은 = 로 복사되지 않지만 구조체는 됩니다.  
> 확인: D3-1 · c = r

### Q1-3. p 가 r 을 가리킬 때 p->h 와 같은 뜻의 표현은 무엇입니까?

```c
Reading r = {25.3, 60, 120};
Reading *p = &r;
```

① *p.h  
**② (*p).h** ✅  
③ p.h  
④ &p->h  

> **정답: ② (*p).h**  
> 해설: -> 는 (*p). 의 줄임입니다. *p.h 는 .이 * 보다 우선이라 *(p.h) 로 읽혀 에러입니다.  
> 확인: D3-1 · p->h

### Q1-4. 구조체를 값으로 넘기는 함수를 호출한 뒤 r.t 는 얼마입니까?

### Q1-5. 배열 인자로 구조체 배열을 받는 함수입니다. a[i].t 와 같은 표현은 무엇입니까?

```c
double avg_t(const Reading *a, int n) {
    double s = 0;
    for (int i = 0; i < n; i++) s += a[i].t;
    return s / n;
}
```

**① (a + i)->t** ✅  
② a->t[i]  
③ *a.t + i  
④ a[i]->t  

> **정답: ① (a + i)->t**  
> 해설: a[i] 는 *(a + i) 이고 그 구조체의 필드이므로 (a + i)->t 와 같습니다. a[i]->t 는 a[i] 가 포인터가 아니라 에러.  
> 확인: 1교시 예제 1-2

### Q1-6. 구조체 두 개가 같은지 == 로 비교하면 어떻게 됩니까?

④ 런타임 에러

> 해설: C 는 구조체 비교 연산자를 제공하지 않습니다. 필드별로 비교하는 함수를 씁니다. memcmp 는 패딩 때문에 믿을 수 없습니다.

## 2교시 · 패딩·정렬·공용체·열거형

### Q2-1. 아래 구조체의 sizeof 가 6 이 아니라 12 인 이유는?

```c
typedef struct { char id; int v; char f; } Bad;
```

① int 가 8바이트라서  
**② int 는 4의 배수 주소에 놓여야 해서 id 뒤 3바이트, 그리고 전체를 4의 배수로 맞추려 f 뒤 3바이트 패딩** ✅  
③ char 가 4바이트로 저장돼서  
④ 컴파일러 버그  

> **정답: ② int 는 4의 배수 주소에 놓여야 해서 id 뒤 3바이트, 그리고 전체를 4의 배수로 맞추려 f 뒤 3바이트 패딩**  
> 해설: 정렬 규칙 ①(필드는 자기 크기 배수 주소) ②(전체 크기는 최대 필드 배수) 두 가지가 모두 작동합니다.  
> 확인: D3-2 · char int char

### Q2-2. 같은 필드를 순서만 바꿨습니다. sizeof 는?

### Q3-1. 아래 연산의 결과를 2진수로 쓰면?

```c
uint8_t a = 0b10110010;
a & 0x0F
```

① 0b10110010  
**② 0b00000010 — 하위 4비트만 남음** ✅  
③ 0b10110000  
④ 0b00001111  

> **정답: ② 0b00000010 — 하위 4비트만 남음**  
> 해설: AND 는 마스크가 1 인 자리만 통과시킵니다. 0x0F = 00001111 이므로 하위 니블만 남습니다.  
> 확인: D3-3 · a & 0x0F

---

### Q3-2. a | 0x01 의 결과는? (a = 0b10110010)

**① 0b10110011 — 최하위 비트가 켜짐** ✅  
② 0b00000001  
③ 0b10110010  
④ 0b01001101  

> **정답: ① 0b10110011 — 최하위 비트가 켜짐**  
> 해설: OR 은 1 을 이기지 못합니다. 마스크의 1 자리가 무조건 1 이 되므로 "켜기"에 씁니다.  
> 확인: D3-3 · a | b

---

### Q3-3. a ^ 0xFF 의 결과는? (a = 0b10110010)

① 0b10110010  
**② 0b01001101 — 전부 반전** ✅  
③ 0b11111111  
④ 0b00000000  

> **정답: ② 0b01001101 — 전부 반전**  
> 해설: XOR 1 은 반전입니다. 0xFF 와 XOR 하면 ~a 와 같고, XOR 은 같은 값을 두 번 하면 원래대로 돌아옵니다.  
> 확인: D3-3 · a ^ 0xFF

---

### Q3-4. 8비트 변수인데 a &lt;&lt; 1 이 356 이 나온 이유는?

```c

```
